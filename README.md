# AI Advent Challenge — День 18

Планировщик погоды: фоновый сбор через MCP и периодическая LLM-сводка.

## Что реализовано

- собственный MCP-сервер `weather`;
- MCP-инструменты:
  - `collect_weather`
  - `save_observation`
  - `read_observations`
  - `save_report`
  - `read_reports`
- по умолчанию планировщиков нет; LLM создаёт их через чат;\n- фоновый планировщик:
  - первый сбор сразу при запуске;
  - далее сбор каждые `20s`;
  - отчёт каждые `60s`;
- наблюдения сохраняются в `data/weather/observations.json`;
- отчёты сохраняются в `data/weather/reports.json`;
- отчёт агрегирует все наблюдения с начала периода:
  - `runCount`
  - min/max/avg температура
  - влажность
  - ветер
  - распределение условий;
- LLM генерирует только текстовую summary по готовым цифрам;\n- запрос и ответ LLM-сводки выводятся в чат отдельным визуальным блоком;
- UI показывает статус, запуски, наблюдения, отчёты;
- есть кнопка «Собрать сейчас»;\n- ручной отчёт можно запросить в чате: «Сформируй отчёт по наблюдениям».

## Запуск

```powershell
go run .
```

Порт: `8088`.

## Переменные окружения

```text
PORT=8088
CITY=Москва
COLLECT_EVERY=20s
REPORT_EVERY=60s
MCP_SERVER=weather
DEEPSEEK_API_KEY_FILE=api_key.txt
```

## Проверка

1. Запустить приложение.
2. Убедиться, что появился первый сбор.
3. Подождать 1–2 минуты.
4. Проверить, что `runCount` растёт.
5. Открыть отчёт: он должен содержать данные всех запусков.
6. Сравнить `runCount` с количеством наблюдений.
